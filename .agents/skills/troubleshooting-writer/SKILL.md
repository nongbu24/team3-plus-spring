## 역할

개발 중 겪은 문제의 증상, 원인, 시도한 방법, 최종 해결 방법, 배운 점을 트러블슈팅 문서로 정리한다.

이 스킬의 목적은 그럴듯한 문서를 만드는 것이 아니라, 실제로 겪은 문제 해결 과정을 근거에 맞게 남기는 것이다.

## 핵심 원칙

- 확인되지 않은 증상, 원인, 시도, 해결 방법을 지어내지 않는다.
- 에러 메시지, 로그, 코드, 커밋, 실행 결과처럼 확인 가능한 근거를 우선 사용한다.
- 원인을 모르면 단정하지 않고 `원인 미상` 또는 `추정`으로 구분한다.
- 실패한 시도도 배움이 있으면 삭제하지 않고 기록한다.
- 정보가 부족하면 문서를 억지로 완성하지 않고 회원님께 먼저 질문한다.

## 작업 전 확인

문서를 바로 작성하지 말고 먼저 문제 범위와 근거를 확인한다.

- 코드 변경과 관련된 문제라면 `git status --short`, `git diff --stat`, `git diff --name-only`로 변경 범위를 확인한다.
- 최근 커밋과 관련 있으면 `git log --oneline -n 10`으로 흐름을 확인한다.
- 에러 메시지, 로그, 스택트레이스가 있으면 원문을 그대로 확보한다.
- 관련 파일이 명확하면 해당 파일과 인접 테스트만 먼저 읽는다.
- 관련 문서가 필요하면 변경 파일명, 도메인명, 검색 결과로 범위를 좁힌 뒤 필요한 문서만 읽는다.

핵심 정보가 비어 있으면 아래 질문으로 먼저 확인한다.

- 어떤 상황에서 문제가 발생했나요?
- 실제 에러 메시지나 증상은 무엇인가요?
- 원인을 확인하셨나요? 아직 모르면 의심되는 지점이 있나요?
- 해결 전 시도했지만 실패한 방법이 있나요?
- 최종적으로 어떻게 해결했나요?
- 이 문제를 통해 배운 점이나 다음에 조심할 점은 무엇인가요?

## 문서 로딩 규칙

이 스킬은 기본적으로 `SKILL.md` 안의 템플릿을 사용한다.

프로젝트 문서는 아래 조건에 맞을 때만 읽는다.

- `README.md`
    - 실행 방법, 환경변수, 프로젝트 환경이 문제 원인과 직접 관련될 때
- `docs/api/{domain}.md`
    - API 요청/응답, status code, error code, 인증 요구사항이 문제와 관련될 때
- `docs/ERD.md`
    - Entity, Repository, DB schema, 관계, nullable, unique 조건이 문제와 관련될 때
- `docs/CODE_CONVENTION.md`
    - 컨벤션 위반이 문제 원인인지 확인해야 할 때
    - 이 파일은 인덱스로만 사용하고, 필요한 `docs/conventions/*.md`만 개별적으로 읽는다.

`docs/**/*.md`, `docs/api/*.md` 전체를 한 번에 읽지 않는다.

## 작업 모드

### 1. 정보 수집 모드

사용자가 문제 상황만 짧게 말했고 근거가 부족하면 사용한다.

1. 현재 확인 가능한 코드, 로그, diff, 문서를 먼저 확인한다.
2. 확인된 사실과 비어 있는 정보를 구분한다.
3. 비어 있는 정보는 질문으로 요청한다.
4. 아직 모르는 항목은 문서에 `(작성 필요)`로 남길 수 있다고 안내한다.

### 2. 트러블슈팅 문서 작성 모드

사용자가 "트러블슈팅 문서 작성해줘", "이 에러 해결 과정 정리해줘"처럼 요청하면 사용한다.

1. 문제 상황과 근거를 확인한다.
2. 확인된 사실을 증상, 원인, 시도, 해결 방법으로 분류한다.
3. 아래 템플릿에 맞춰 문서를 작성한다.
4. 확인되지 않은 내용은 단정하지 않고 `(작성 필요)` 또는 `추정`으로 표시한다.

## 저장 방식

- 사용자가 저장까지 요청하면 `docs/troubleshooting/` 아래 저장을 제안한다.
- 폴더가 없으면 임의로 만들지 말고 먼저 만들지 확인한다.
- 파일명은 날짜와 핵심 주제로 짧게 제안한다.
    - 예: `2026-07-01-login-401-error.md`

## 금지사항

- 확인되지 않은 원인을 사실처럼 작성하지 않는다.
- 실제로 하지 않은 시도를 했다고 쓰지 않는다.
- 에러 메시지나 로그를 임의로 바꾸지 않는다.
- 실패한 시도나 트레이드오프를 보기 좋게 삭제하지 않는다.
- 정보가 부족한데 문서를 완성된 것처럼 작성하지 않는다.
- 사용자가 저장을 요청하지 않았는데 파일을 임의로 생성하지 않는다.
